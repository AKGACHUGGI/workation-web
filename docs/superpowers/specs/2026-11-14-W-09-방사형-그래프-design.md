# W-09 시군구 그래프 방사형 설계 (유형 3개)

- 작성일: 2026-11-14
- 상태: 승인됨 (브레인스토밍 결과, 2026-11-13~14)
- 고치는 문서: [v6 설계](./2026-11-13-W-09-지도탐색-v6-design.md) §3-2 ① 확대 · §5 · §7 · §8 · §12 · §13. 이 문서에 없는 내용은 v6 그대로다
- 백엔드 짝 문서: workation-backend `docs/superpowers/specs/2026-11-14-explore-type-3-design.md` (브랜치 `docs/explore-type-3`). 유형 3개 · 대표 유형 기준 40점 · 핀 `topType` null 규칙은 그쪽이 기준
- 경로: `/explore?sgg={id}`

## 1. 목표

사용자가 시군구를 열었을 때 **"어떤 스타일로 일하고 싶은가 → 그 스타일에 맞는 동은 어디인가"**에 바로 답한다. 자세한 사실(등급·시간대·한산한 달·브리핑)은 동을 눌러 본다.

v6 힘 기반 그래프의 문제:

- 동 하나에 선이 최대 5개(유형·바닷가·생활·조용함·저녁 활기)라 얽힌다.
- 정해진 모양이 없어 "어느 동이 어느 유형인지"를 위치로 읽을 수 없다.
- 등급·생활권은 이미 유형 점수의 재료라 같은 정보가 두 번 나온다(몰입형 ≈ 조용함, 네트워킹형 ≈ 저녁 활기, 로컬살이형 = 생활권 지수).

## 2. 결정 요약

| 항목                  | 결정                                                                           | 이유                                                                                                  |
| --------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 모양                  | **방사형**: 가운데 시군구 → 안쪽 링 유형 3 → 바깥 링 동                        | 위치 = 유형. 동마다 선 1개                                                                            |
| 유형                  | 몰입형 · 네트워킹형 · 로컬살이형 (장기체류형 삭제)                             | 백엔드 짝 문서 §2                                                                                     |
| 유형 없음             | 1위 < 40 (`topType = null`) 동은 아래쪽 "뚜렷한 유형 없음" 구역, 시군구와 점선 | 약한 1위를 유형으로 보이지 않는다. 별도 "유형 없음" 노드는 만들지 않는다(공통점이 아닌데 허브가 된다) |
| 다른 사실             | 바닷가만 동 원에 🌊 표시. 등급 · 생활권/관광지 노드와 관계 칩 삭제             | 바닷가는 유형과 별개이고 사용자가 많이 따지는 조건. 나머지는 유형과 중복                              |

| 끌기                  | 삭제                                                                           | 위치가 정보라 옮기면 잘못 읽힌다                                                                      |
| 동 클릭               | v6 그대로 (선택 카드 → 동네 자세히 보기)                                       | 사용자 결정                                                                                           |
| v6 "시군구 노드 없음" | 뒤집음. 시군구 노드를 가운데에 그린다                                          | 방사형의 중심이자 "유형 없음" 동을 잇는 자리                                                          |

```
     성덕🌊   ╲     ╲  ╱     ╱

                   │
 송정🌊 ╲          │                ╱ 경포🌊
         (몰입형) ─ [강릉시] ─ (네트워킹형) ── 중앙
 연곡🌊 ╱          ┊                ╲ 초당🌊
                   ┊                  옥천
             ┊  ┊  ┊  ┊  ┊

```

(강릉 실측 기준: 로컬살이형 10 · 네트워킹형 4 · 몰입형 2 · 유형 없음 5. 🌊 위치는 형식 예시)

- 헤더: v6 그대로 `강릉시` · `강원특별자치도 · 행정동 21곳`.
- 관계 칩 줄(`RelationChips`) 없음. 그 자리에 범례 한 줄: `● 워케이션 유형  🌊 바닷가  ┊ 뚜렷한 유형 없음`.
- 노드:
  | 노드        | 모양                                                   | 크기                                    |
  | ----------- | ------------------------------------------------------ | --------------------------------------- |
  | 시군구      | 진한 회색 채운 원 + 흰 글자                            | 고정(유형보다 크게)                     |
  | 유형        | `primitive/arches/500` 채운 원 + 흰 글자 (v6 유형 색)  | 고정                                    |
  | 동          | 흰 원 + `brand/primary` 테두리 + 아래 이름 (v6 그대로) | 지름 ∝ `topScore`. `null`이면 최소 크기 |
  | 바닷가 표시 | 동 원 오른쪽 위 작은 🌊 배지 (`coastal`)               | 고정                                    |
- 선: 시군구─유형(실선), 유형─동(실선), 시군구─유형 없음 동(점선). 선 위 글자 없음.
- 유형 없음 구역 아래 안내 한 줄: `뚜렷한 유형이 없는 동네예요. 눌러서 자세히 보세요.` 유형 없음 동이 0이면 구역과 문구가 없다.
- 이어진 동이 0인 유형 노드는 그리지 않는다.

## 4. 배치 규칙 (`features/explore/radialLayout.ts`)

순수 함수 `radialLayout(pins: PinDong[], size: {w, h}) => { nodes: PositionedNode[]; links: GraphLink[] }`.

1. 무리 나누기: 동을 `topType`별로, `null`은 "없음" 무리로.
2. 각도 몫: 무리마다 `동 수 / 전체 동 수 × 360°`. "없음" 무리는 아래쪽(90°, 화면 기준 6시 방향)을 가운데로 둔다. 유형 무리는 나머지 각도를 시계 방향으로 몰입형 → 네트워킹형 → 로컬살이형 순서로 차지한다.
3. 유형 노드: 반지름 `R1`, 자기 무리 각도의 가운데.
4. 동 노드: 반지름 `R2`, 자기 무리 각도 안에 고르게. 무리 안 순서는 점수 높은 순으로 가운데부터 바깥쪽으로 번갈아(가운데 = 1등). `null` 무리는 이름 가나다순.
5. 동이 많아 바깥 링 한 줄에 겹치면(이웃 동 간격 < 동 지름 + 이름 여백) 두 번째 링 `R3`에 번갈아 놓는다. 전주시(34동)가 최대.
6. `R1` · `R2` · `R3`는 그래프 영역(`GRAPH_W` × `GRAPH_H`)의 짧은 변 기준 비율. 같은 입력이면 같은 좌표(난수 없음).

## 5. 상호작용 (v6 §5와 다른 점)

| 동작             | 결과                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------ |
| 동 클릭          | v6 그대로: 그 동과 이어진 선·노드만 진하게(나머지 18%) + 선택 카드                         |
| 유형 노드 클릭   | 그 유형의 동만 진하게 + 카드에 `로컬살이형 · 동 10곳` 목록 (v6 사실 노드 클릭과 같은 방식) |
| 시군구 노드 클릭 | 선택 해제 (빈 곳 클릭과 같음)                                                              |
| 끌기             | 없음                                                                                       |
| 키보드           | v6 그대로: Tab으로 유형 → 동 순서, Enter로 선택                                            |

선택 카드의 `공통 N: …`(공통 사실 많은 동 최대 3)은 **그래프 선이 아니라 핀 데이터**로 센다. 비교하는 사실: 대표 유형 · 바닷가 · 생활권/관광지 · 조용함 등급 · 저녁 활기 등급(v6에서 칩을 다 켰을 때와 같은 기준). 카드 모양은 v6 그대로.

## 8. 테스트

### Vitest

- `radialLayout`: 각도 몫이 동 수에 비례, "없음" 무리가 아래쪽, 같은 입력 같은 좌표, 무리 안 1등이 가운데, 34동에서 겹침 없음(이웃 간격 ≥ 지름), 이어진 동 0인 유형 노드 없음.
- `buildSigunguGraph`: 시군구 노드 1, 유형─동 실선, 시군구─`null` 동 점선, 등급·생활 노드 없음.
- `sharedFacts`: 핀 데이터 기준 공통 사실 수·정렬.
- `SigunguGraph.test.tsx`: 유형 노드 클릭 → 카드 목록, 🌊 배지, 유형 없음 안내 문구.
- 기존 테스트의 `장기체류형` 기대값 교체.
