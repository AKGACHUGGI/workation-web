## 1. 목적

행정동 하나의 "하루 리듬"과 성격을 보여준다. 시군구 상세(W-03)가 "언제 가면 좋은가"라면, 동네 프로필은 "여기서 일하면 하루가 어떻게 흘러가는가"다. 24시간 보행 곡선, 활동 유형 비중, 비슷한데 더 조용한 동네 추천이 핵심이다.

### 3-1. 히어로

- 브레드크럼: `탐색(/)` › `{sigungu.name}(/regions/{sigungu.id})` › `{name}`.
- 메타: `{province} · {month 라벨} · {buildDongSummary(...)}` (§6).
- 태그: `DONG_KIND_LABEL[kind]` · `tags[]` · `ACTIVITY_LABEL[dominantActivity]`.
- 공유(URL 복사) · 저장(로그인 필요 → W-07). 갤러리는 W-03 `PhotoGallery` 재사용.

### 3-2. ScoreCard

| 요소     | 값                                                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 큰 숫자  | `scores.quiet` (tier dong 응답)                                                                                                         |
| 한 줄    | `동네 조용함 · 행정동 {total}곳 중 백분위 {score} · {grade}`                                                                            |
| 세부     | `{month} 기준 · 저녁 활기 {g} · 또래 밀도 {g} · 생활권 지수 {localLife}`                                                                |
| 요약 4칸 | 주중 피크 `{peaks.weekday.peakHour}시` / 가장 한산 `{peaks.weekday.lowHour}시` / 낮 유입 지수 `{dayInflow}` / 생활권 지수 `{localLife}` |

- `total`은 tier dong 응답 `items.length`(마스킹·특수시설 제외 후, 10월 203).

### 3-3. 24시간 붐빔 곡선 (`HourlyCurveChart`, Recharts)

- 데이터: `hourly.weekday[24]`, `hourly.weekend[24]` (0~100, 둘 중 최대 = 100).
- 월 칩: 선택 `month` ±1개월(연간이면 `연간 · 9월 · 10월` 대신 최근 3개월). 클릭 → `month` 쿼리 변경(`push`).
- 주중/주말 토글(`Segmented`, 로컬 상태 `day`): 선택한 선은 진하게, 다른 선은 옅게(둘 다 표시).
- X축 0·3·6·9·12·15·18·21·23시, Y축 숨김, 툴팁 `{h}시 · 주중 {v} · 주말 {v}`.
- 아래 3칸: 주중 피크 `{h}시 · 100` / 가장 한산 `{h}시 · {v}` / 주말 피크 `{h}시 · 100`.
- 캡션: `시간대별 보행인구 · 최대 시간대 = 100 · GET /dongs/{id}?month=`.
- 전환 애니메이션은 Recharts 기본(300ms).

### 3-4. 동네 성격 (NEW, `ActivityMixBar`)

- 제목 "동네 성격", 캡션 "24시간 보행 패턴을 4개 유형으로 분해 · 비중 합 100".
- 가로 누적 막대 1개(4색, `chart-*` 토큰) + 범례 4줄: `주말 관광형 32% · 저녁 상권형 25% · 평일 업무형 24% · 새벽 주거형 19%` (큰 순).
- 한 줄 요약 = 히어로 메타 문장과 동일(`buildDongSummary`).
- 같은 컴포넌트를 W-05 비교에서 열마다 사용.

### 3-5. 동네 지표 4종 (`MetricCard` ×4)

| 카드        | 점수           | 등급                             | 부제                                                            |
| ----------- | -------------- | -------------------------------- | --------------------------------------------------------------- |
| 동네 조용함 | `scores.quiet` | `metricGrade`                    | `낮 유입 지수 {dayInflow} · 백분위 {score}`                     |
| 저녁 활기   | `scores.vibe`  | `metricGrade`                    | `저녁 유동 ÷ 체류 {eveningVibe} · 규모 대비 {eveningSurplus}배` |
| 또래 밀도   | `scores.peer`  | `metricGrade`                    | `20~40대 방문 비율 {peerShare}%`                                |
| 생활권 지수 | `localLife`    | 고정 경계(≥70 A, ≥50 B, 그 외 C) | `(거주+근무) ÷ 전체 {localLife}% · {생활권                      | 혼합 | 방문지}` |

- 생활권 지수는 티어 지표가 아니라 태그 성격이므로 tier 응답이 아닌 상세 응답 값을 쓴다. 캡션 `{month} · 행정동 {total}곳 백분위 (특수시설 {excluded}곳 제외)`.

### 3-6. 위치 (`DongMap`)

- 구글맵, 초기 뷰는 `bbox`에 맞춤. 소속 시군구의 행정동 폴리곤을 모두 그리되 현재 동만 `brand` 색 채움(불투명 0.35)·굵은 외곽선, 나머지는 회색 외곽선만. 현재 동 중심에 `MapPin` 마커 + 이름.
- 다른 동 폴리곤 클릭 → `/dongs/{id}` 이동(쿼리 유지). 현재 동 hover 시 `{name} · 동네 조용함 {grade}` 툴팁.
- 우측 캡션 `accessNote`(수동 데이터, 예: "고성군 북부 · 속초 시외버스터미널에서 40분"), 하단 `landmarks.join(' · ')`.
- `VITE_GOOGLE_MAPS_KEY`가 없으면 같은 크기의 회색 박스에 "지도 키가 설정되지 않았습니다 · landmarks 텍스트" 표시. mock·CI·E2E는 이 상태로 돈다.

### 3-7. 비슷한데 더 조용한 동네 3곳 (NEW, `QuieterTwinsSection`)

- 제목 "비슷한데 더 조용한 동네", 캡션 "활동 유형 · 계절 유형 · 또래 · 보행 밀도 · 낮 유입이 비슷하면서 방문객이 더 적은 다른 시군구의 동".
- 카드 3개(`TwinCard`): 사진(소속 시군구 사진) · 이름 · `{sigunguName}` · `유사도 {similarity}` · `방문객 {visitorRatio}배` · `동네 조용함 {GradeBadge}`.
- 카드 클릭 → `/compare?dongs={현재 id},{대상 id}` (쿼리 유지). 0개면 섹션 숨김.

### 3-8. 워케이션 노트 · 체감 투표

- W-03 `NoteSection`, `PollSection` 재사용. 엔드포인트만 dong(§5). 투표 질문: `{name} 저녁, 정말 조용한가요?`(기본) — 저녁 활기 등급 S·A면 `{name} 저녁, 정말 활기찬가요?`. 캡션 `{n}명 참여 · 저녁 활기 지수 검증에 반영돼요`.

### 3-9. 비교하기 링크

- "다른 동네와 나란히 비교하기 · 행정동 2~3개의 24시간 곡선과 지표를 비교합니다 (W-05)" → `/compare?dongs={id}`.

## 5. API 계약

### 5-1. 재사용

- `GET /api/tier?month={month}&scope=dong` → `rankIn(items, dongId, { tab: 'metric', metric: 'quiet' })` 로 점수·순위·등급. 세부 등급은 `items[i].scores`.
- `GET /api/tier?month={month}&scope=sigungu` → PlanCard 소속 시군구 요약.

### 5-2. `GET /api/dongs/{dongId}?month={month}`

```ts
// features/dong/types.ts
export type ActivityKey = 'eveningDowntown' | 'weekendTourist' | 'weekdayWork' | 'dawnResidential'

export type DongDetailResponse = {
  id: string
  name: string // 거진읍
  sigungu: { id: string; name: string }
  province: string
  kind: DongKind // 'living' | 'tourist' (W-03 공유 타입)
  tags: string[] // ['해안']
  photos: { url: string; credit?: string }[]
  landmarks: string[] // ['거진읍', '거진항', '화진포'] 수동
  accessNote: string // 수동
  month: MonthParam
  stats: {
    dayInflow: number // 평일 낮 체류 ÷ 새벽 체류
    localLife: number // (거주+근무) ÷ 전체 × 100, 정수
    peerShare: number // 20~40대 방문 비율 %, 정수
    eveningVibe: number // 평일 저녁 보행 ÷ 평일 저녁 체류, 소수 2자리
    eveningSurplus: number // 실제 ÷ 예측 저녁 보행, 소수 2자리
  }
  hourly: { weekday: number[]; weekend: number[] } // 길이 24, 0~100, 두 배열 중 최대 = 100 (annual: 12개월 평균)
  peaks: {
    weekday: { peakHour: number; lowHour: number; lowValue: number }
    weekend: { peakHour: number; lowHour: number; lowValue: number }
  }
  activityMix: Record<ActivityKey, number> // 정수, 합 100
  seasonType: SeasonType // W-03 공유 타입
  quieterTwins: {
    id: string
    name: string
    sigunguId: string
    sigunguName: string
    similarity: number // 0~1, 소수 2자리
    visitorRatio: number // 대상 방문객 ÷ 현재 방문객, 소수 2자리 (< 1)
    photoUrl: string
  }[] // 최대 3, 유사도 내림차순
  bbox: [number, number, number, number] // [minLng, minLat, maxLng, maxLat]
  special?: 'special_facility' // 특수시설 플래그 동일 때만
}
```

산출 규칙(계약):

- `hourly`는 해당 월의 요일 그룹(weekday/weekend)별 시간대 평균 보행인구를 두 그룹 공통 최대값으로 나눠 100 기준으로 만든다.
- `activityMix`는 24시간 NMF 4유형 비중을 합 100으로 정규화해 정수 반올림(합이 100이 되도록 최대 항목에서 보정).
- `quieterTwins`의 `visitorRatio`는 연간 평균 방문객 기준. 유사도 0.6 미만은 제외.
- `peaks.lowValue`는 0~100 정규화 값(거진읍 주중 3시 48).

### 5-3. 폴리곤

- `public/geo/{sggId}.json`: 시군구 단위 행정동 폴리곤 FeatureCollection(`properties.id`, `properties.name`). 통계청 행정동 경계를 단순화(허용 오차 20m)해 시군구당 ≤ 100KB. 생성 스크립트 `scripts/gen-geo.py`(원본 shp는 저장소에 넣지 않음).
- 쿼리 키 `['geo', sggId]`, `staleTime: Infinity`.

### 5-4. 커뮤니티

- `GET /api/dongs/{id}/notes?sort=helpful&cursor=` → `NotesResponse` (W-03과 동일 타입)
- `GET /api/dongs/{id}/poll?month=` → `PollResponse`

### 쿼리 키

`['dong', id, { month }]`, `['dong', id, 'notes', { sort }]`, `['dong', id, 'poll', { month }]`, `['geo', sggId]`, 재사용 `['tier', { month, scope: 'dong' }]`, `['tier', { month, scope: 'sigungu' }]`.

## 6. 계산·문구 사전 (`features/dong/`)

- `ACTIVITY_LABEL`: eveningDowntown "저녁 상권형", weekendTourist "주말 관광형", weekdayWork "평일 업무형", dawnResidential "새벽 주거형".
- `dominantActivity(mix)`: 최대 비중 키.
- `buildDongSummary({ dominant, weekdayPeakHour, vibeGrade, kind })` → 한 문장. 템플릿:
  - weekendTourist: `주말에 사람이 몰리고 평일 낮 {h}시가 피크인 {kindLabel} 동네` + 저녁 활기 C·B면 `, 저녁엔 일찍 조용해집니다` / S·A면 `, 저녁까지 활기가 이어집니다`
  - eveningDowntown: `저녁 {h}시에 가장 붐비는 상권형 동네, 낮엔 상대적으로 조용합니다`
  - weekdayWork: `평일 낮 {h}시에 붐비고 주말엔 한산한 업무형 동네`
  - dawnResidential: `아침·밤에 사람이 있고 낮엔 비는 주거형 동네, 일하기엔 가장 조용합니다`
- `localLifeLabel(v)`: ≥70 "생활권", ≥50 "혼합", 그 외 "방문지".
- `pollQuestion(name, vibeGrade)`.
- 시각 표기 `formatHour(11) → '11시'`.
