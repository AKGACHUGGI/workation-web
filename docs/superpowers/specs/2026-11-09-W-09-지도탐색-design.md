## 1. 목적

검색어 없이 **태그를 고르고 지도를 움직이며** 워케이션 후보 동네를 찾는 페이지. 동네·태그·장소가 어떻게 이어져 있는지를 **지도 위에 그래프로** 보여준다.

- 태그를 고르면 그 태그가 있는 동네가 지도에 뜨고(①), 동네를 누르면 동 이름을 중심으로 고른 태그마다 색 가지가 실제 위치의 장소로 이어진다(②). 장소를 누르면 정보가 열린다(③).
- 그래프 전체를 진입 시 한 번 받으므로, 이후 모든 클릭은 서버 요청 없이 즉시 반응한다.

### 3-0. 태그 바

| 묶음 (색)                 | 태그                                                                      | ②에서                              | 판정 (백엔드)                                     |
| ------------------------- | ------------------------------------------------------------------------- | ---------------------------------- | ------------------------------------------------- |
| 동네 성격 (회색 계열, 새) | 바닷가 `coast`, 도심 `city`                                               | 배지 (바닷가는 `해안 {coastKm}km`) | 해안선 거리 1km 이내 / 팀 시트                    |
| 일하기 (분홍)             | 카페 많음 `cafe`, 도서관 `library`                                        | 가지 + 장소 핀                     | 관광공사 장소 3곳 이상 / 1곳 이상                 |
| 머물기 (청록)             | 장기 숙소 `long_stay`, 리조트 `resort`                                    | 가지 + 장소 핀                     | 1곳 이상 (장기 숙소 = 콘도·레지던스·게스트하우스) |
| 쉬기 (초록)               | 해수욕장 `beach`, 공원 `park`, 산·숲 `mountain`, 섬 `island`, 서핑 `surf` | 가지 + 장소 핀 (산·숲은 배지)      | 1곳 이상 (산·숲은 팀 시트)                        |
| 생활 (주황)               | 시장 `market`                                                             | 가지 + 장소 핀                     | 1곳 이상                                          |

- 칩은 묶음 색·아이콘, 묶음 사이 구분선. 선택된 칩은 묶음 색 테두리 + 연한 배경 + 체크.
- 4번째 태그를 누르면 토스트 "태그는 3개까지 고를 수 있어요".

### 확대 단계와 지도 표시

| 줌    | 태그 선택 전(⓪)                       | 태그 선택 후(①)                           |
| ----- | ------------------------------------- | ----------------------------------------- |
| ~8    | 도 4곳 라벨                           | 도별 해당 동 수 배지 (예: "전북 8곳")     |
| 9~10  | 시군구 경계 + 라벨 `동 6 · 카페 14`   | 해당 동 표시(`TagMatchMarker`)            |
| 11~13 | 행정동 경계 + 라벨 `카페 12 · 숙소 8` | 해당 동 표시 + 경계 강조                  |
| 14+   | 장소 핀 + 클러스터                    | 고른 태그의 장소 핀만, 나머지 흐리게(0.4) |

- 라벨의 숫자는 그 범위 장소 수(`places` 집계). 태그 선택 전 라벨은 `카페 {cafe 장소 수} · 숙소 {long_stay + resort 장소 수}`, 시군구 단계는 앞에 `동 {동 수}`를 붙인다.
- 집계 제외 동은 회색 점선 영역 + 라벨 "집계 제외", 클릭 불가, 태그 표시 대상 아님. **현재 대상 없음**: 유일한 제외 동인 고성군 수동면은 경계 자료가 없어 응답·GeoJSON에 모두 없다(시안의 회색 영역은 규칙 예시). `excluded: true`인 동이 응답에 생기면 이 규칙을 적용한다.
- 경로 바와 확대 단계는 지도가 멈춘 뒤 200ms 후 갱신. 경로 항목·단계 칩을 누르면 그 범위로 이동.

### 3-1. ⓪ 기본 상태 (374:7720)

- 태그 바 모두 꺼짐.
- 패널 "이 지도 범위 요약": 안내 카드("위쪽 태그를 골라 보세요") + 이 범위의 태그 막대 목록(태그가 있는 동 수, 묶음별). 막대 행을 눌러도 태그 바와 같이 선택된다.

### 3-2. ① 태그 선택 → 해당 동 표시 (367:7210)

- 고른 태그가 있는 동마다 `TagMatchMarker`: 색 점(해당 태그) + 동 이름. 고른 태그를 **모두** 가진 동은 검정(`match=all`), 일부만은 흰색(`partial`).
- [하나라도 있는 동 N | 모두 있는 동 M]. "모두"면 `partial`을 숨긴다. 태그 1개면 전환 버튼을 숨긴다.
- 화면 밖 해당 동은 왼쪽 아래 도 칩(`↙ 전북특별자치도 8곳`). 누르면 그 도의 해당 동이 모두 보이게 이동.
- 표시 hover: 툴팁 `{동} · {태그} {n} · … / 누르면 {동} 중심 그래프로 확대` (배지 태그는 숫자 없이 이름만).
- 패널: 고른 태그 칩 + "모두 있는 동 · 장소 많은 순" 목록(최대 4, 행 클릭 = 표시 클릭) + "태그 더 고르기" 막대 목록.

### 3-3. ② 동 클릭 → 동 중심 그래프 (368:7485)

- 지도가 그 동 `bbox`에 맞춰 확대(패딩 80px), 스포트라이트.
- 지도 그래프:
  - 중심 노드: 동 이름(`GraphNode kind=dong center=true`)을 `center`에.
  - 가지 태그(`display: 'branch'`)마다 허브(`GraphNode kind=tag`, 라벨 `카페 많음 · 7`). 위치는 그 태그 장소들 무게중심과 중심 노드의 중간.
  - 중심 → 허브 5px, 허브 → 장소 핀 2px, 묶음 색.
  - 장소 핀: 실제 좌표 `PlacePin`. 가지당 5개(중심에서 가까운 순), 나머지는 허브 옆 `+N곳 더`(누르면 패널 목록으로 스크롤).
  - 배지 태그(`display: 'badge'`) 중 고른 것은 중심 노드 아래 배지: `바닷가 · 해안 0.4km`, `도심`, `산·숲`.
  - 고른 가지 태그가 그 동에 없으면 허브를 만들지 않고 패널에 "이 동네엔 {태그} 장소가 없어요".
- [← 태그 지도로 돌아가기 · N곳] → ①, 직전 지도 뷰 복원. 태그 바는 그대로 남아 태그를 더하거나 빼면 가지가 즉시 바뀐다.
- 패널(위→아래): 동 이름·`{도} · {시군구}`, 지표 등급 글자 `동네 조용함 S · 또래 밀도 A · 저녁 활기 B`(S 상위 25% / C 하위 25%, 등급 없으면 줄 숨김), "이 동네의 특징" 태그 칩(고른 태그 강조), 고른 가지 태그별 장소 목록(3개 + 모두 보기), **비슷한 동네**(최대 3: `{동} · {시군구}`, 겹치는 태그, 클릭 → 그 동 중심 ②), 데이터 한계 문구, 하단 [동네 프로필 보기 →](W-04 `/dongs/{id}`).

### 3-4. ③ 장소 선택 (375:8233)

- ② 상태에서 핀 또는 패널 장소 행 클릭. 선택 핀 `PlacePin selected=true` + 이름 말풍선, 그 가지 4px 강조, 다른 핀·가지 흐리게.
- 패널: [← {동}으로], 대표 사진(없거나 로드 실패면 태그 아이콘 타일), 장소명 + "장소" 태그, 태그 칩, `소속 동 {동} · {시군구}`(클릭 → ②), 출처 박스 "사진·장소 정보 출처: 한국관광공사", "같은 가지의 다른 장소" 3개, 하단 [{동} 동네 프로필 보기 →].
- 장소 소개 문장은 데이터에 없으므로 넣지 않는다(시안의 소개 문장은 삭제 예정, §13).

## 5. URL 상태

| 키      | 값                        | 기본값 |
| ------- | ------------------------- | ------ |
| `tags`  | 태그 id 콤마 구분, 최대 3 | 없음   |
| `match` | `any` \| `all`            | `any`  |
| `dong`  | 행정동 id (②)             | 없음   |
| `place` | 장소 id (③, `dong` 필요)  | 없음   |

- 공통 기반 `useQueryState`. `tags`·`match`는 `replace`, `dong`·`place` 진입은 `push`(뒤로 가기 = 한 단계 위).
- 지도 중심·줌은 URL에 넣지 않는다. `dong`이 있으면 그 `bbox`, 없으면 강원 동해안 기본 뷰.
- 없는 id·4개 이상 태그·`dong` 없는 `place` → 해당 값을 지우고 한 단계 위로.

## 6. API 계약 — `GET /api/explore/graph`

진입 시 1회, 파라미터 없음. 쿼리 키 `['explore', 'graph']`, `staleTime: Infinity`. 백엔드는 배치로 만든 그래프(Neo4j 복사본 + 캐시)에서 이 형식으로 응답한다.

```ts
// features/explore/types.ts
export type LatLng = { lat: number; lng: number }
export type TagGroup = 'trait' | 'work' | 'stay' | 'rest' | 'life'

export type ExploreGraphResponse = {
  syncedAt: string // ISO 8601
  tags: {
    id: string // 'cafe' · 'coast' …  (food 없음)
    label: string // '카페 많음'
    group: TagGroup // coast·city = 'trait'
    display: 'branch' | 'badge' // coast·city·mountain = 'badge'
  }[] // 12개, 태그 바 표시 순서: coast, city, cafe, library, long_stay, resort, beach, park, mountain, island, surf, market
  provinces: { id: string; name: string; center: LatLng | null }[] // id = 시군구 코드 앞 2자리 (강원 51, 전북 52, 전남 46, 제주 50)
  sigungu: { id: string; name: string; provinceId: string; center: LatLng | null }[] // id = sigungu_code 5자리
  dongs: {
    id: string // adm_code 10자리 (W-04와 동일)
    name: string
    sigunguId: string
    center: LatLng | null // 경계 내부 점(ST_PointOnSurface). 현재 응답 동은 모두 값 있음
    bbox: [number, number, number, number] // [west, south, east, north], 소수 5자리
    grades: { quiet: Grade | null; peer: Grade | null; evening: Grade | null } | null // 연간. 셋 다 없으면 null
    tags: { tagId: string; placeCount: number | null }[] // tags와 같은 순서. badge 태그는 null, branch인데 장소 0곳이면 0
    coastKm: number | null // 해안 거리, 내륙(약 18km 초과)·경계 없음은 null
    similar: string[] // 비슷한 동 id, 순위순 최대 5, 다른 시군구 포함, 집계 제외 동은 후보 아님
    excluded?: true // 형식만 유지. 현재 집계 제외 동(수동면)은 경계·adm_code가 없어 응답에 포함되지 않음
  }[]
  places: {
    id: string // TourAPI contentid
    name: string
    dongId: string
    lat: number
    lng: number
    tag: string // branch 태그 하나 (mountain 근거 장소는 넣지 않음)
    image: string | null // https URL. 바꿀 수 없으면 null
  }[]
}
```

계약 규칙:

- 음식점(`food` 근거) 장소와 `food` 태그는 넣지 않는다.
- `dongs[].tags[].placeCount` = 같은 응답 `places` 중 그 동·그 태그 수. badge 태그는 `null`. branch 태그인데 0이면(장소가 경계 밖으로 빠진 경우 등) ②에서 허브를 만들지 않는다.
- 정렬: `places`는 id 문자열 순, `dongs`·`sigungu`·`provinces`는 id 순. 모든 id는 문자열.
- `image`는 백엔드가 `http://` → `https://`로 바꿔 준다(관광공사 이미지 https 200 확인). 그 밖의 주소는 `null`.
- 장소 수 추정: 음식점·산·숲 근거 제외 약 870곳(동 경계 매핑 전).
- `similar`는 연간 `metric_vec` 거리 상위 5(백엔드 계획과 같음). 웹은 ② 패널에 앞 3개만 쓰고, 겹치는 태그는 두 동의 `tags`로 계산한다.
- 압축 응답 100KB 이하 목표(백엔드 계획과 같음).
- 오류: 503 `{"error": {"code": "GRAPH_UNAVAILABLE", "message": "탐색 데이터를 불러오지 못했어요."}}` → §9 오류 화면.

### 폴리곤

W-04 §5-3의 `public/geo/{sggId}.json` 재사용. 줌 11 이상에서 화면에 걸친 시군구 파일만 불러온다(`['geo', sggId]`).

## 7. 계산 (`features/explore/`)

- `indexGraph(res)` → 조회용 맵: 태그별 동, 동·태그별 장소, id별 동·장소. 받은 직후 1회.
- `matchDongs(index, tagIds, mode)` → `{ dongId, matched: tagId[], all: boolean }[]`. `excluded` 제외.
- `countOffscreen(matches, bounds)` → 도별 화면 밖 개수.
- `summarizeTags(index, bounds)` → 범위 안 태그별 동 수(⓪ 패널).
- `layoutBranches(dong, places, tagIds)` → 가지 태그별 허브 좌표, 표시 장소 5개 + 나머지 수. 배지 태그는 `badges` 배열로 분리.
- `sharedTags(a, b)` → 비슷한 동네 행의 겹치는 태그.
- `gradeLabel(grades)` → `동네 조용함 S · 또래 밀도 A · 저녁 활기 B`. 값이 `null`인 지표는 빼고, 모두 없으면 줄을 숨긴다.
- 지도 이동 후 범위 계산은 200ms 디바운스.
