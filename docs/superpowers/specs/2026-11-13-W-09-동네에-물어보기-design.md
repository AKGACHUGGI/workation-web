- 백엔드 짝 문서: workation-backend `docs/superpowers/specs/2026-11-13-explore-ask-design.md` (브랜치 `feat/explore-ask`). 응답 형식은 두 문서 §5가 같다
- 구현 위치: 워크트리 `workation-web-w09` (`feat/W-09-explore`)

## 1. 목표

② 동 패널에서 그 동네에 대해 자유 문장으로 묻고, 답이 대화처럼 쌓인다. 답은 그래프의 사실로만 만든 1~3문장이다(백엔드 그래프 RAG).

완료 기준:

- 브리핑 칸 아래에 예시 칩 3개와 입력창이 있고, 칩을 누르거나 입력해서 보내면 질문·답이 쌓인다.
- 동을 바꿨다 돌아와도 그 동의 대화가 남아 있다(새로고침하면 사라진다).
- 대기·오류·모르는 질문·횟수 초과가 모두 화면에 처리된다.
- mock 모드(`VITE_USE_MOCK=true`)에서 백엔드 없이 동작한다.

## 2. 결정 요약

| 항목          | 결정                                                                                | 이유                                            |
| ------------- | ----------------------------------------------------------------------------------- | ----------------------------------------------- |

| 표시          | 질문(오른쪽)·답(왼쪽)이 아래로 쌓임                                                 | 사용자 결정                                     |

## 3. 화면

```
┌ 이 동네에서 일하는 하루 ─────────────────────┐
│ (기본 브리핑 3문장, v6 와 같음)                 │
│                                                │
│                     오전에 일하기 조용해?   ◀ 질문: 오른쪽 말풍선
│ 평일엔 9시가 가장 한산해서 오전 업무에 맞아요.  ◀ 답: 왼쪽, 브리핑과 같은 글자
│                                                │
│ [이 동네 조용해?] [주말엔 …?] [비슷한 동네는…?] ◀ 예시 칩 3개
│ ┌───────────────────────────────┐ ┌──┐        │
│ │ 이 동네에 대해 물어보세요       │ │ ↑ │       ◀ 입력 + 보내기
│ └───────────────────────────────┘ └──┘        │
└────────────────────────────────────────────────┘
```

- **칩**: 누르면 그 문장으로 바로 보낸다. 칩 모양은 v6 선택 가능 칩(테두리·hover)과 같다.
- **입력**: 1~100자. 100자를 넘으면 더 입력되지 않고 `98/100`처럼 남은 글자 수를 보인다. Enter로 보내고, IME 조합 중 Enter는 무시한다.
- **대기**: 질문 말풍선이 바로 붙고, 답 자리에 점 3개(`animate-skeleton-pulse`, reduced-motion 처리 그대로). 대기 중에는 칩·입력·보내기 비활성.
- **스크롤**: 새 질문·답이 붙으면 그 말풍선이 보이도록 패널을 부드럽게 내린다(`scrollIntoView({block: 'nearest'})`, reduced-motion이면 즉시).
- **모르는 질문**(`source: "guide"`): 답 자리에 안내 문구, 칩은 응답의 `examples`.
- **오류**:

| 상황         | 답 자리                                                       |
| ------------ | ------------------------------------------------------------- |
| 네트워크·503 | 지금은 답을 가져오지 못했어요. [다시 시도]                    |
| 429          | 잠시 후 다시 물어봐 주세요. (다시 시도 없음)                  |
| 400          | 질문은 1~100자로 적어 주세요. (입력 제한 때문에 보통 안 생김) |

- 접근성: 대화 목록은 `role="log"` `aria-live="polite"`, 입력은 `aria-label="이 동네에 물어보기"`.
- 칸 높이: v6 `DONG_SECTION_H.briefing`(`min-h-25`)은 그대로 최소 높이, 내용만큼 늘어난다. ② 패널은 원래 세로 스크롤.

**Figma**: 기존 ②-v6(436:9725)은 고치지 않는다. 대화 칸(기본·대기·답·모르는 질문·오류) 프레임을 ②-v6 오른쪽에 새로 추가한다(구현 계획의 첫 Task).

## 4. 데이터

### 4-1. 타입 (`src/features/explore/types.ts`에 추가)

```ts
export type AskSource = 'llm' | 'mixed' | 'rule' | 'guide'
export type AskResponse = {
  question: string
  answer: string[]
  intents: string[]
  source: AskSource
  examples: string[]
}
export type AskTurn =
  | { id: string; question: string; status: 'pending' }
  | { id: string; question: string; status: 'done'; answer: string[]; source: AskSource }
  | { id: string; question: string; status: 'error'; kind: 'retry' | 'limit' | 'invalid' }
export type AskThread = { turns: AskTurn[]; examples: string[] }
```

### 4-2. 요청과 기록

- `api.ts` `askDong(id, question): Promise<AskResponse>` — `POST /api/explore/dongs/{id}/ask`.
- `useAskThread(dongId)`: 기록을 `queryClient`의 `exploreKeys.askThread(id)`에 두고(`gcTime: Infinity`, 서버 요청 없는 로컬 캐시), `ask(question)`·`retry(turnId)`를 돌려준다. 컴포넌트가 내려가도 동별로 남는다.
- 첫 칩 3개 = 백엔드 대표 질문 중 `이 동네 조용해?` · `평일엔 몇 시가 붐비고 몇 시가 한산해?` · `비슷한 동네는 어디야?` (copy.ts 상수).
- mock: `src/mocks/explore/ask.ts` — 질문에 `밥`·`맛집`·`카페`가 있으면 `guide`, 그 밖은 의도별 고정 답(주문진읍·금암동 실측 값, 그 밖 동은 핀 값으로 결정적 생성). `VITE_MOCK_DELAY` 적용.

## 5. API

백엔드 문서 §5와 같다: `POST /api/explore/dongs/{dongId}/ask` `{question}` → `{question, answer, intents, source, examples}`, 오류 400 `QUESTION_INVALID` · 404 `DONG_NOT_FOUND` · 429 `TOO_MANY_REQUESTS` · 503 `GRAPH_UNAVAILABLE`.


## 7. 테스트

- 단위: 칩 누르면 전송·칩 교체, 입력 Enter 전송·IME 중 무시, 100자 제한, 대기 중 비활성, 쌓이는 순서, `guide` 표시, 503 → 다시 시도 → 성공, 429 표시, 동 A → B → A 기록 유지.
- E2E(`e2e/explore.spec.ts`): mock 으로 주문진읍 열기 → 칩 하나 → 답 1개 보임.
