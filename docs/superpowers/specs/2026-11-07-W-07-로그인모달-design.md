## 1. 목적

로그인은 즐겨찾기·팁·투표·사진처럼 쓰기 동작에만 필요하다. 읽기 화면은 전부 비로그인으로 동작하며, 쓰기 동작을 시도할 때 이 모달이 뜬다. 인증은 **백엔드 OAuth 리다이렉트**로 처리하고 프론트는 세션 상태만 읽는다.

## 3. 화면 구성

### 3-1. LoginModal (440px, Figma 263:4425)

```
┌──────────────────────────────────┐
│ [로고] 워케이션맵              × │
│                                  │
│ 당신의 장소를 찾으세요             │
│                                  │
│ [● 카카오로 시작하기]  (노랑)      │
│ [● Google로 시작하기] (흰색 테두리)│
│                                  │
│        로그인 없이 둘러보기        │
└──────────────────────────────────┘
```

- 스크림(`scrim` 토큰) 위 가운데. `Esc`·스크림 클릭·×·"로그인 없이 둘러보기" 모두 닫기.
- 버튼 클릭 → 버튼 로딩 상태(스피너, 둘 다 비활성) → `window.location.assign(startUrl)`.
- 제공자 아이콘은 각사 브랜드 가이드의 공식 심볼 SVG(`public/brand/kakao.svg`, `google.svg`). 색은 카카오 `#FEE500` 배경·검정 글자, Google 흰 배경·회색 테두리 — 브랜드 규정 색이므로 토큰 예외로 `@theme`에 `--color-brand-kakao`, `--color-brand-google-border`로 등록한다.
- 접근성: `role="dialog"` `aria-labelledby`(제목), 포커스 트랩, 열릴 때 첫 버튼에 포커스, 닫히면 열었던 요소로 복귀.

### 3-2. OnboardingModal (첫 로그인 전용, Figma 없음)

- 제목 "거의 다 됐어요", 닉네임 입력(2~12자, 기본값 제공자 닉네임), 체크박스 2개(이용약관 · 개인정보 처리방침, 각 링크), `시작하기` 버튼(둘 다 체크 + 닉네임 유효 시 활성).
- 완료 → `PATCH /api/auth/me { nickname, agreedAt }` → 원래 하려던 동작 재개.
- 닫으면 로그아웃 처리(`POST /api/auth/logout`) — 약관 미동의 상태로 세션을 남기지 않는다.

### 3-3. Navbar 연동

- 비로그인: 우측 `로그인` 버튼 → 모달. 로그인: 아바타(이니셜) → 드롭다운 `마이페이지(/me)` · `로그아웃`.
- Navbar 스펙은 공통 기반 §4. 이 문서는 로그인 상태 분기만 추가한다.

## 4. 흐름과 URL

```
[쓰기 동작 클릭] → useRequireLogin() → 비로그인이면 LoginModal 열기 (pendingAction 기억)
  → [카카오] → location.assign(`${API}/api/auth/kakao/start?redirect=${encodeURIComponent(현재 URL + '&login=1')}`)
  → 카카오 로그인 → 백엔드 콜백: 세션 쿠키 발급 → 302 redirect 파라미터로 복귀
  → 앱 로드 → `login=1` 감지 → GET /api/auth/me 재검증
      → needsOnboarding ? OnboardingModal : (토스트 "로그인했습니다")
      → `login=1` 제거(replace). pendingAction은 페이지 리로드로 사라지므로 복귀 후 재개하지 않는다(사용자가 다시 클릭)
  → 실패: 콜백이 `?login=error&reason=…`으로 복귀 → 토스트 "로그인에 실패했습니다. 다시 시도해 주세요"
```

- `redirect`는 백엔드가 **같은 origin만 허용**(오픈 리다이렉트 방지). 프론트는 path+query만 보낸다.
- 로그인 상태는 `useAuth()`(TanStack Query `['auth','me']`, `staleTime` 5분, 401이면 `null`)로 전역 공유. 로그아웃 시 캐시 무효화.

## 5. API 계약

```ts
// features/auth/types.ts
export type AuthProvider = 'kakao' | 'google'
export type Me = {
  id: string
  nickname: string
  initial: string // 아바타용 1글자
  provider: AuthProvider
  emailMasked: string // 'du***@kakao.com'
  needsOnboarding: boolean // 약관 미동의 또는 닉네임 미설정
  createdAt: string
}
```

| 엔드포인트                                 | 설명                                                                                   |
| ------------------------------------------ | -------------------------------------------------------------------------------------- |
| `GET /api/auth/{provider}/start?redirect=` | 제공자 인증 페이지로 302. 백엔드가 state 저장                                          |
| `GET /api/auth/{provider}/callback`        | 백엔드 전용. 세션 쿠키 발급 후 `redirect`로 302 (`login=1` 또는 `login=error&reason=`) |
| `GET /api/auth/me`                         | 200 `Me` / 401 비로그인                                                                |
| `PATCH /api/auth/me`                       | `{ nickname?, agreedAt? }` → `Me`                                                      |
| `POST /api/auth/logout`                    | 204, 쿠키 삭제                                                                         |
| `DELETE /api/auth/me`                      | 계정 삭제(W-08)                                                                        |

- 쿠키: `HttpOnly; Secure; SameSite=Lax`. 개발 환경은 Vite proxy로 같은 origin 유지(`/api` → 백엔드).
- CSRF: 쓰기 요청은 `SameSite=Lax` + 커스텀 헤더 `X-Requested-With: workation-web` 요구(백엔드 확인). `api<T>()`에 헤더 추가.
- mock 모드: `start` 호출 대신 `mockLogin(provider)`가 `['auth','me']`를 가짜 사용자로 채우고 `needsOnboarding=true`로 OnboardingModal을 띄운다. 리다이렉트 없음.

## 6. 컴포넌트·훅

```
features/auth/
  types.ts, api.ts, useAuth.ts, useRequireLogin.ts (+ .test.ts), useLoginReturn.ts
  components/
    LoginModal.tsx (+ .test.tsx), SocialLoginButton.tsx
    OnboardingModal.tsx (+ .test.tsx)
    AuthMenu.tsx                 Navbar 우측 (로그인 버튼 / 아바타 드롭다운)
  AuthProvider.tsx               모달 열림 상태·pendingAction 컨텍스트. RootLayout에서 감싼다
components/ui/Modal.tsx          재사용
components/ui/Checkbox.tsx, TextField.tsx   온보딩용 (Figma 토큰 기준, 시안은 열린 항목)
```

- `useRequireLogin()` → `(action: () => void) => void`. 로그인 상태면 즉시 실행, 아니면 모달.
- 공통 기반에서 스텁으로 두었던 "로그인이 필요합니다" 토스트를 이 훅으로 교체한다(W-03·W-04·W-05 호출부 변경 없음).

## 9. 테스트

### Vitest

- `useRequireLogin`: 비로그인 → 모달 열림·action 미실행, 로그인 → 즉시 실행
- `LoginModal`: 버튼 2개, 클릭 시 `start` URL(제공자·redirect 인코딩), Esc 닫기, 포커스 트랩
- `OnboardingModal`: 닉네임 길이 검증, 체크 2개 전 버튼 비활성, 닫기 시 logout 호출
- `useLoginReturn`: `login=1` → me 재검증 + 쿼리 제거(replace); `login=error` → 토스트

### Playwright E2E (mock)

1. **모달**: `/regions/51820` → `이 지역 즐겨찾기` 클릭 → 모달 "당신의 장소를 찾으세요", 버튼 "카카오로 시작하기"·"Google로 시작하기", `로그인 없이 둘러보기`로 닫힘.
2. **가입 흐름**: 카카오 버튼 → 온보딩 모달 → 약관 2개 체크 + 닉네임 → 시작하기 → Navbar에 아바타 "두".
3. **로그아웃**: 아바타 → 로그아웃 → Navbar `로그인` 버튼 복귀.
