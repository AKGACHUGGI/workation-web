## 1. 목표

② 동 패널에서 그 동네에 대해 이어서 묻는다. 같은 시군구의 다른 동네 이름을 말하면 서버가 비교해서 답한다(GraphRAG, LangGraph 대화 기억).

완료 기준:

- 브리핑 칸 안에 대화 목록, 예시 질문 3개, 입력창이 있고 칩·입력으로 보내면 질문과 답이 쌓인다.
- 이어 묻기가 된다("경포동이랑 비교하면?" 다음 "주말엔?"이 두 동네 비교로 답해진다).
- 동을 바꿨다 돌아와도 그 동의 대화가 남아 있다. 새로고침하면 사라진다.
- 대기·오류·모르는 질문·다른 시군구 안내·횟수 초과가 화면에 처리된다.
- mock 모드(`VITE_USE_MOCK=true`)에서 백엔드 없이 동작한다.

## 2. 결정 요약

| 항목      | 결정                                                                       | 이유                                              |
| --------- | -------------------------------------------------------------------------- | ------------------------------------------------- |
| 위치·모양 | v6.1 그대로: 브리핑 카드 안, 브리핑 3문장 아래로 대화가 쌓임               | 기존 Figma·스펙 재사용                            |
| 대화 단위 | 동마다 따로. 동 A → B → A 면 A 대화가 남아 있음                            | 사용자 결정                                       |
| 기준 칩   | 넣지 않음. `criteria.chips` 는 늘 `[]`                                     | 사용자 결정. 서버가 관심 기록·등급 차로 축을 고름 |
| 근거(ⓘ)   | 보여 주지 않음. 응답의 `evidence` 는 쓰지 않음                             | 사용자 결정("이상해짐")                           |
| 색        | Airbnb 가이드: Rausch 는 보내기 원형 버튼 하나. 질문 말풍선은 `brand-soft` | 사용자 결정(A안) + 가이드 "한두 곳"               |
| 서버 기억 | `conversationId` 를 동별 대화에 저장해 다음 요청에 보냄. 서버 TTL 30분     | 백엔드 스펙 §8                                    |
| 기록 저장 | 화면이 떠 있는 동안만(TanStack Query 캐시). 서버에 질문 원문 저장 없음     | v6.1 과 같음                                      |

서버가 30분 지나 대화를 잊으면 새 `conversationId` 를 돌려준다. 화면의 대화는 그대로 두고 id 만 바꾼다(이어 묻기 맥락만 끊긴다).

## 3. 화면

Figma 상태 번호를 따른다. 1~5 는 v6.1 과 같은 구성에 색만 바뀌었다.

| 상태          | 내용                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------- |
| 1 기본        | 브리핑 3문장 + 예시 질문 3개 + 입력창                                                                         |
| 2 대기        | 질문 말풍선이 바로 붙고 답 자리에 점 3개. 칩·입력·보내기 비활성(보내기는 연한 Rausch)                         |
| 3 답          | 답 문장은 왼쪽, 브리핑과 같은 글자. 칩은 응답 `examples` 로 바뀜                                              |
| 4 모르는 질문 | 응답 `guide` 를 회색(`text-secondary`)으로                                                                    |
| 5 오류        | 503·네트워크 → "지금은 답을 가져오지 못했어요." + [다시 시도]. 429 → "잠시 후 다시 물어봐 주세요."(버튼 없음) |
| 6 비교 답     | 문장 2~3개를 한 줄씩(문장마다 줄을 나눔)                                                                      |
| 7 이어 묻기   | 대화가 길어지면 대화 목록만 스크롤(최대 높이 288 = `max-h-72`). 새 말풍선이 보이게 내림                       |
| 8 다른 시군구 | 응답 `guide` 를 회색으로. 칩은 응답 `examples`                                                                |

스타일 (토큰만, 임의값 금지):

- 질문 말풍선: `bg-brand-soft border border-brand-soft-border text-text-primary`, 오른쪽 정렬, 모서리 16 · 오른쪽 아래만 4.
- 보내기: 40×40 원형 `bg-brand-primary hover:bg-brand-hover`, 흰 화살표. 비활성 `bg-rausch-100`.
- 입력창: 알약 모양(`rounded-full`), `border-border-default`, 100자.
- 예시 질문: 기존 v6 칩과 같은 흰 알약 + `border-border-default`.

입력·접근성은 v6.1 §3 그대로: 1~100자, 남은 글자 수, Enter 보내기·IME 조합 중 무시, 대화 목록 `role="log"` `aria-live="polite"`, 입력 `aria-label="이 동네에 물어보기"`.

## 4. 데이터

### 4-1. 타입 (`src/features/explore/types.ts`)

```ts
export type ChatSource = 'llm' | 'mixed' | 'rule'
export type ChatSentence = { text: string; source: ChatSource }
export type ChatResponse = {
  conversationId: string
  dongs: { id: string; name: string }[]
  intent: string
  sentences: ChatSentence[]
  guide: string | null
  examples: string[]
}
export type ChatTurn =
  | { id: string; question: string; status: 'pending' }
  | {
      id: string
      question: string
      status: 'done'
      sentences: ChatSentence[]
      guide: string | null
    }
  | { id: string; question: string; status: 'error'; kind: 'retry' | 'limit' | 'invalid' }
export type ChatThread = { conversationId: string | null; turns: ChatTurn[]; examples: string[] }
```

응답의 `evidence` 는 타입에 두지 않는다(쓰지 않음). 모르는 질문·다른 시군구·시군구 이름만 말함은 `sentences` 가 비고 `guide` 만 온다. 동 4개 이상이면 `guide`("앞의 세 곳만 볼게요")와 비교 `sentences` 가 함께 온다 → `guide` 를 회색으로 먼저, 문장을 그 아래에.

### 4-2. 요청과 기록

- `api.ts` `postChat(body): Promise<ChatResponse>` — `POST /api/explore/chat`, 본문 `{conversationId, panel, question, criteria: {chips: [], interest}}`.
- `interest` = `{metric, terrain, recent}`. 관심 모듈에 `chatInterest(): {metric, terrain, recent}` 를 추가해 `index.ts` 로 내보낸다. `buildProfile(getEvents(), Date.now())` 의 `metric` · `terrain` 과, `place` 중 10자리 행정동 코드를 무게 순으로 3개(`recent`). 기록이 없으면 빈 객체·빈 배열.
- `useChatThread(dongId)`: 기록을 `exploreKeys.chatThread(id)` 에 둔다(`gcTime: Infinity`, 로컬 캐시). `ask(question)` · `retry(turnId)` 를 돌려준다. 응답의 `conversationId` 를 그 동 기록에 저장한다.
- 오류 종류: 429 → `limit`, 400 → `invalid`, 그 밖(503·404·네트워크) → `retry`.
- 첫 칩 3개 = v6.1 과 같음(`이 동네 조용해?` · `평일엔 몇 시가 붐비고 몇 시가 한산해?` · `비슷한 동네는 어디야?`).
- mock: `src/mocks/explore/chat.ts`. 질문에 `밥`·`맛집`·`카페` → `guide`(백엔드 unknown_place 문구). 핀 목록의 같은 시군구 동 이름이 있으면 비교 답 2문장 + `dongs` 2개, 다른 시군구 동 이름이면 `guide`(백엔드 문구 그대로). 그 밖은 의도별 고정 답. `conversationId` 는 `mock-<dongId>`. `VITE_MOCK_DELAY` 적용.

## 5. 컴포넌트

#16 에서 지운 파일(`git show 2cb8e13^:<경로>`)을 되살려 고친다.

```
components/panel/ChatThread.tsx   (← AskThread) Briefing 카드 안: 대화 목록 + 예시 질문 + 입력
components/panel/ChatBubble.tsx   (← AskBubble) 질문·답·대기·오류 하나. 답은 문장마다 한 줄
components/panel/ChatInput.tsx    (← AskInput) 알약 입력 + 원형 보내기
features/explore/useChatThread.ts (← useAskThread)
```

`Briefing.tsx` 는 `children` 을 받아 카드 안 브리핑 아래에 그린다(v6.1 때와 같은 모양). `DongPanel` 의 `Briefing` 자리에 `ChatThread` 를 넣는다. 문구는 `copy.ts` `EXPLORE_COPY` 에 v6.1 의 `ask*` 문구를 `chat*` 이름으로 되살린다.

## 6. 테스트

- 단위: 칩 누르면 전송·칩 교체, Enter 전송·IME 중 무시, 100자 제한, 대기 중 비활성, 쌓이는 순서, guide 회색, 503 → 다시 시도 → 성공, 429 표시, 동 A → B → A 기록 유지, 두 번째 요청에 첫 응답의 `conversationId` 가 실림, 요청 `criteria.chips` 가 `[]`.
- `chatInterest`: 기록 없음 → 빈 값, 행정동 조회 기록 → `recent` 상위 3개(시군구 코드는 제외).
- E2E(`e2e/explore.spec.ts`): mock 으로 주문진읍 열기 → 칩 하나 → 답 보임 → "경포동이랑 비교하면?" 입력 → 문장 2개 보임.
