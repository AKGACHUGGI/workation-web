# workation-web 개발 가이드

이 문서는 처음 레포를 받은 팀원이 환경을 맞추고, 화면을 추가하고, PR 을 올리기까지 필요한 규칙을 정리합니다.

## 1. 환경 설정

### 필수 도구

| 도구    | 버전              | 설치                                                                |
| ------- | ----------------- | ------------------------------------------------------------------- |
| Node.js | 22 이상 (권장 26) | `nvm install` (`.nvmrc` 참조) 또는 [nodejs.org](https://nodejs.org) |
| pnpm    | 11.5              | `corepack enable` 후 자동 설치                                      |
| 에디터  | VS Code 권장      | 아래 확장 설치                                                      |

### VS Code 확장

- `esbenp.prettier-vscode` — 저장 시 자동 포맷
- `bradlc.vscode-tailwindcss` — Tailwind 클래스 자동완성
- `oxc.oxc-vscode` — oxlint 진단 표시

`.vscode/settings.json` 에 아래를 두면 저장 시 포맷이 걸립니다 (개인 설정이라 커밋하지 않음).

```json
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true
}
```

### 처음 한 번

```bash
git clone https://github.com/TEAM-SKPJC/workation-web.git
cd workation-web
corepack enable
cp .env.example .env
pnpm install
pnpm dev
```

브라우저에서 `http://localhost:5173` 이 열리고 "웹 초기 구성이 완료되었습니다" 문구가 보이면 정상입니다.

## 2. 일상 작업 흐름

브랜치·커밋·PR·라벨 규칙의 기준 문서는 [협업 규칙](https://github.com/TEAM-SKPJC/workation-docs/blob/main/협업/협업-규칙.md) 입니다. 아래는 그 요약입니다.

1. 이슈 템플릿(✨ Feature / 🐛 Bug / ♻️ Refactor / ❗ Etc)으로 이슈를 먼저 만들고 이슈 번호를 받습니다
2. `main` 에서 브랜치 생성: `feat/W-02-region-detail` 처럼 `타입/화면ID-설명`
3. 개발하며 `pnpm dev` 로 확인
4. 커밋 전 `pnpm lint && pnpm format:check && pnpm build && pnpm test` 가 모두 통과하는지 확인합니다
5. PR 생성. PR 템플릿의 `🔗 이슈` 에 `close #번호` 를 적으면 merge 시 이슈가 자동으로 닫힙니다. GitHub Actions CI(`pnpm lint`, `pnpm format:check`, `pnpm build`, `pnpm test`, `pnpm e2e`)가 자동 실행되며 결과가 PR 에 표시됩니다
6. CI 가 초록색이면 `main` 에 squash merge (merge commit·rebase 는 레포 설정에서 비활성화)

### 커밋 메시지

Conventional Commits 를 따릅니다.

```
feat: W-02 지역 상세 화면 레이아웃
fix: 추천 카드 이미지 비율 깨짐 수정
chore: 의존성 업데이트
docs: 개발 가이드 보강
refactor: ScoreDisplay 컴포넌트 분리
style: 포맷만 변경 (로직 변화 없음)
```

## 3. 화면 추가하기

명세서의 화면 ID(W-01~W-08)와 1:1 로 파일을 만듭니다.

1. `src/pages/RegionDetailPage.tsx` 생성 (PascalCase + `Page` 접미사)
2. `src/router.tsx` 의 `children` 에 라우트 등록

```tsx
import RegionDetailPage from '@/pages/RegionDetailPage'

children: [
  { index: true, element: <HomePage /> }, // W-01
  { path: 'regions/:sggId', element: <RegionDetailPage /> }, // W-03
]
```

3. 화면에서만 쓰는 컴포넌트·훅·API 호출은 `src/features/<도메인>/` 아래에 모읍니다.
   예: `src/features/region/useRegionDetail.ts`, `src/features/region/RegionHeader.tsx`
4. 두 화면 이상에서 재사용되면 `src/components/` 로 올립니다.

## 4. 코드 규칙

### TypeScript

- `strict` 계열 옵션이 켜져 있습니다. `any` 는 쓰지 않고, 외부 데이터는 타입을 명시합니다.
- `verbatimModuleSyntax` 때문에 타입만 가져올 때는 `import type { Foo } from '...'` 을 씁니다.
- `erasableSyntaxOnly` 때문에 `enum`, `namespace`, 매개변수 프로퍼티(`constructor(private x)`)는 쓸 수 없습니다. 상수 객체 + 유니언 타입으로 대체합니다.
- 미사용 변수·매개변수는 컴파일 에러입니다. 의도적으로 무시하려면 `_` 접두사를 붙입니다.

### React

- 함수 컴포넌트 + `export default function`. 파일 1개 = 컴포넌트 1개.
- 훅 규칙(`react/rules-of-hooks`)은 에러로 잡힙니다.
- 컴포넌트 파일에서 컴포넌트 외의 값을 export 하면 HMR 경고가 납니다(`only-export-components`). 상수는 별도 파일로 분리합니다.
- 서버 데이터 호출은 `src/lib/api.ts` 의 `api<T>()` 를 통해서만 합니다. 컴포넌트 안에서 `fetch` 를 직접 쓰지 않습니다.

### Tailwind

- 색상·폰트·라운드·그림자·타이포는 `src/index.css` 의 `@theme` 토큰만 사용합니다. `text-[#222]` 같은 임의값은 금지합니다.
- 의미 토큰을 우선 씁니다: 본문 `text-text-primary`, 보조 `text-text-secondary`, 헤어라인 `border-border-default`, CTA `bg-brand-primary hover:bg-brand-hover`, 선택 상태 `bg-selected-bg text-selected-fg`. 원시 팔레트(`bg-rausch-500`)는 의미 토큰이 없을 때만 씁니다.
- 텍스트 크기는 `text-heading-xl` 같은 스타일 이름 하나로 size·line-height·weight 가 함께 적용됩니다. `text-xl font-bold` 처럼 조합하지 않습니다.
- 클래스 순서는 Prettier 플러그인이 자동 정렬하므로 신경 쓰지 않아도 됩니다.
- 토큰을 추가할 때는 `@theme` 에 `--color-*`, `--font-*`, `--radius-*` 네이밍으로 넣으면 Tailwind 유틸리티가 자동 생성됩니다.

```css
@theme {
  --color-babu: #00a699; /* → bg-babu, text-babu */
  --radius-card: 14px; /* → rounded-card */
}
```

### 네이밍

| 대상           | 규칙                   | 예                            |
| -------------- | ---------------------- | ----------------------------- |
| 컴포넌트 파일  | PascalCase             | `ScoreDisplay.tsx`            |
| 훅             | `use` 접두사 camelCase | `useRegionDetail.ts`          |
| 유틸·타입 파일 | camelCase              | `formatScore.ts`, `region.ts` |
| 라우트 경로    | kebab-case             | `/regions/:regionId`          |

## 5. 환경 변수 추가

1. `.env.example` 에 변수와 설명 추가
2. `src/vite-env.d.ts` 의 `ImportMetaEnv` 에 타입 추가
3. 코드에서 `import.meta.env.VITE_XXX` 로 접근

`VITE_` 접두사가 없는 변수는 클라이언트 번들에 포함되지 않습니다. 비밀 키는 어떤 경우에도 프론트에 두지 않습니다.

### 로그인·쿠키 (W-07)

- 세션은 백엔드가 발급하는 HttpOnly 쿠키다. 프론트는 토큰을 저장하지 않고 `GET /api/auth/me` 로 상태만 읽는다 (`useAuth`).
- 개발 서버는 `vite.config.ts` 의 proxy 로 `/api` 를 `VITE_API_BASE_URL` 에 넘긴다. 그래서 `lib/api.ts` 는 `DEV` 에서 상대 경로(`''`)를, 빌드에서는 `VITE_API_BASE_URL` 을 쓴다.
- 쓰기 동작 앞에는 `useRequireLogin()` 을 건다. 비로그인이면 로그인 모달이 뜨고, 로그인 뒤 보류한 동작이 재개된다(같은 페이지일 때).
- `VITE_USE_MOCK=true` 면 카카오·Google 버튼이 리다이렉트 없이 가짜 사용자 "두이"로 로그인한다.
- 제공자 심볼은 `public/brand/` 의 공식 파일만 쓴다 (`public/brand/README.md`).

## 6. 빌드와 배포

```bash
pnpm build     # dist/ 생성
pnpm preview   # 빌드 결과 확인
```

`dist/` 는 정적 파일이므로 Vercel, Netlify, Cloudflare Pages, S3 등 어디든 올릴 수 있습니다. SPA 라우팅을 쓰므로 호스팅 설정에서 모든 경로를 `index.html` 로 리라이트해야 합니다. 배포 플랫폼은 미정입니다.

## 7. 자주 겪는 문제

| 증상                                    | 원인 / 해결                                                                                              |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `npm install` 이 실패함                 | pnpm 전용 레포입니다. `corepack enable && pnpm install`                                                  |
| `@/...` import 를 못 찾음               | `tsconfig.app.json` 의 `paths` 와 `vite.config.ts` 의 `alias` 양쪽에 있어야 합니다. 에디터 재시작도 시도 |
| 저장해도 Tailwind 클래스가 안 먹음      | `src/index.css` 가 `main.tsx` 에서 import 되는지, 클래스가 임의값 아닌 토큰인지 확인                     |
| `pnpm build` 에서 `TS5101 baseUrl` 에러 | TypeScript 6 에서 `baseUrl` 이 폐기되었습니다. `paths` 만 쓰고 `./src/*` 처럼 상대 경로로 지정           |
| HMR 경고 `only-export-components`       | 컴포넌트 파일에서 상수나 함수를 함께 export 한 경우. 별도 파일로 분리                                    |
